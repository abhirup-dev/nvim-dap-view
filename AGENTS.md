# Agent instructions

This project uses **Beads (`bd`)** for durable tasks, dependencies and blockers.
Run `bd prime` when context is missing or stale; it supplies the detailed workflow.

Issues live in a local Dolt database. Sync uses `refs/dolt/data` on the Git remote,
separately from code branches. `.beads/issues.jsonl` is a passive export, not the
source of truth or normal sync mechanism. See [Beads sync concepts](https://github.com/gastownhall/beads/blob/main/docs/core-concepts/sync-concepts.md).
On a new machine, use `bd bootstrap --yes`, not a fresh `bd init`. Follow
[the project sync workflow](.beads/README.md) for authorized pull/push operations
and preserved recovery history.

## Non-interactive shell commands

Use non-interactive flags to avoid confirmation prompts:

- Files: `cp -f`, `mv -f`, `rm -f`; recursive operations: `cp -rf`, `rm -rf`.
- SSH/SCP: `-o BatchMode=yes`.
- Package operations, when authorized: `apt-get -y` and `HOMEBREW_NO_AUTO_UPDATE=1`.

## Task workflow

- Use `bd` for all task tracking; do not use TodoWrite, TaskCreate or Markdown TODO lists.
- Inspect and claim work with `bd ready`, `bd show <id>`, `bd update <id> --claim`.
- File discovered follow-up work and dependencies in Beads.
- Keep persistent project knowledge in `bd remember`, not `MEMORY.md` or ad hoc memory files.
- Close tasks with `bd close <id>` only when the work is actually complete.

## Git authority and handoff

The default conservative/minimal profile does **not** authorize commits, pushes
or Dolt remote sync. These require explicit user authorization. Team-maintainer
behavior applies only when the repository explicitly opts in. Current user and
orchestrator instructions take precedence, including any prohibition on pushing.

Before ending implementation work:

1. File remaining work, run relevant quality gates, and update task status.
2. Run `git status` and follow the active authorization/profile for commits and sync.
3. Report changed files, validation, issue status and remaining steps.
4. If a required sync or push is blocked, stop and report its exact command and error.

Without authorization, report proposed Git/sync commands rather than executing them.
